### A-290 — the store-details Sync tab had no client permission gate
- **Fixed:** 2026-10-19, `web/` only, TDD. Full reasoning in `web/AGENTS.md`, "The Sync tab is gated on `view_platform_health` (A-290)".
- **Was:** all five panels of the tab are server-gated on `view_platform_health` (`routes/api.php`), but `StoreDetailTabs` gated nothing. A `platform_admin` or `agent` without that permission saw a **Sync** tab and landed on five cards each rendering its own "unavailable" state from a 403. The panel-level *actions* were already gated, so the convention and the helper both existed; only the container was never gated.
- **Now:** `checkHasPermission(user, "view_platform_health")` hides the `TabsTrigger` and the `TabsContent`, `resolveTab()` takes the same flag so a shared `?tab=sync` link resolves to `overview`, and `StoreSyncTab` repeats the check itself so it does not depend on its caller (A-135's lesson). Hide, never disable, matching the three action components beside it.
- **The badge is suppressed rather than degraded.** `syncVerdict()` would have returned `Unavailable` off the two 403s — honest, but an alarm on a tab nobody can open, and two 403s on every store page view. The two hooks are passed `enabled: canViewSync` instead, so the verdict is `null` and the existing "no pill, empty live region" path renders.
- **No browser smoke test was possible here (§9), so the clicks are written down** in the `AGENTS.md` section above: an operator without the permission must see a two-tab strip, a `?tab=sync` deep link must open Overview, and the network tab must show no `table-agreement`/`stock-divergence` request; granting the permission must bring all five panels back.
- **Backward compatibility (§11):** client-side only and strictly subtractive — the server already refused these calls, so nothing that used to work stops working.
- **Coverage:** `web/__tests__/admin-store-sync-tab-gating.test.tsx` — 6 cases, 4 RED before (no trigger, no content, the `?tab=sync` fallback, the two queries staying disabled, and `StoreSyncTab`'s own guard). The two permitted cases were green before and exist to pin that the gate is not inverted. `admin-store-detail-tabs.test.tsx` gained an auth-store mock: it had none, so every one of its Sync assertions would otherwise have been passing on an unauthenticated user.
